# 文章骨架与语感

按类型取骨架。骨架是顺序，不是必须填满的目录；没有内容的节删掉，不写占位。所有类型共用文末的语感规则。

## 原理 / 机制长文

问题与现象 → 机制（按数据流或控制流分步，配一张主图）→ 边界与反例 → 结论与适用条件。
先让读者看到问题为什么难，再展开机制；不要开篇讲背景百科。

## 实战复盘

现象与影响 → 定位（假设—验证循环，写清被推翻的假设）→ 根因 → 修复 → 预防与回归。
保留失败路径，比只写最终修复更有复用价值。区分“当时证据”与“事后解释”。

## 性能记录

指标与基线 → 环境与版本 → 方法 → 结果（分布、对比、误差）→ 结论边界 → 复现命令。
数字给基线、单位、测量条件与运行次数；单次结果不作为结论。结论不超出测过的形状和设备。

## 入门 / 概念科普

一个具体场景 → 最小概念 → 逐步展开 → 常见误解。
每引入一个抽象先给一个可操作的例子；避免一次塞入完整体系。

## 设计 / 决策文档

约束与目标 → 方案 → 取舍（对比表，列代价而非只列优点）→ 影响面与人机接口 → 未决事项。
写清非目标和被否方案的理由；未定方案标注为待确认，不伪造成已决。

## 论文粗读 / 精读

- 粗读：用四问收尾——解决什么问题、方法是什么、证据是否支持结论、局限在哪。只做判断，不复述全文。
- 精读：假设是否成立、方法细节能否复现、实验是否公平（基线、数据、算力）、可复用点、复现风险。区分作者主张与你的判断。

## 语感规则

- 中文直接陈述，短句为主，少用破折号和“不仅仅是……而是……”式排比。
- 先定义再使用；同一个概念只用一个词。
- 观点写成“在 X 条件、Y 代价下选 Z”，不写成口号。
- 不写“众所周知”“显而易见”“赋能”“闭环”等空词。
- 结尾给结论与边界，不重复全文摘要。
